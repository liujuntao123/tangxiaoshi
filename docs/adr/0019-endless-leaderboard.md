# 无尽排行榜：纪录向、从存档派生

日期：2026-09-06
状态：有效

## 背景与问题

无尽模式（`/endless`，ADR-0011/0015 口径）只记录玩家个人的最高连对与最高分（`PlayerSave.endlessBestStreak / endlessBestScore`），成绩无法被看见：短局挑战缺少一层「我的纪录在同伴中处于什么位置」的轻反馈。需求是给无尽模式增加排名系统。

但项目红线（根目录 `AGENTS.md`、`docs/game-design.md` §3）明确不做「排行榜压迫」：榜单不能变成催更、嘲讽、赛季焦虑或奖励绑架的工具。因此要回答两个问题：榜单展示什么、数据从哪来。

## 决策

1. **纪录向、无压迫**。榜单只展示前 20 名的最好成绩与玩家自己的名次；不做赛季、段位、榜单奖励、倒计时或任何惩罚；没上榜只给一句「答对 1 题就能上榜」的鼓励。入口是开场/结算面板上的主动按钮，不打扰、不弹窗、不推送，答题界面不受任何影响。
2. **双榜，与「双最佳」口径一致**。连对榜为主榜（与结算页「本局连对」主口径一致），得分榜并列；两榜都用严格更优人数 + 1 的竞赛排名，并列同名次（1,2,2,4）。
3. **从 `player_saves` 派生，不建新表**。榜单就是 `endless_best_score / endless_best_streak` 的全局视图：单一真相、零迁移（Neon 与 PGLite 均无需变更）、零新增写路径，榜单与个人纪录永远不会分叉。实现为 `getEndlessBoard`（GET server fn，挂 `authMiddleware`），每次打开榜单现查现算：双榜各取前 20 名、榜上总人数、自己的两个名次。
4. **隐私最小化**。接口只返回展示名（`user.name`，注册时取邮箱前缀；缺行或空名回退「无名小诗」，截断 12 字）、双最佳成绩、名次与 `isSelf` 标志，绝不返回 userId 或邮箱；没有留过纪录（连对与得分均为 0）的玩家不上榜。
5. **渲染端防御**。`normalizeEndlessBoard` 纯函数（`src/lib/game/leaderboard.ts`）在服务端出库后与客户端渲染前各跑一次：脏行丢弃、数值钳制、展示名兜底截断、名次按榜单指标重算；配套 `leaderboard.test.ts` 直测。

## 后果

- **实时性**：刚结束的一局要等 `writeSave` 落库后才出现在榜上（存档写入通常亚秒级），榜单页每次打开重新拉取，可接受。
- **查询成本**：名次与人数是全表聚合，玩家量为家庭/班级级（< 1 万）时成本可忽略；若未来规模变大，再给 `endless_best_score / endless_best_streak` 加降序索引或改物化榜。
- **不设赛季刷新**：榜单是全历史纪录榜；若以后要做周期榜，另立 ADR。
- 展示名沿用账号名（邮箱前缀）：本产品自托管、受众为熟人规模，不上传额外资料；若未来公开部署，需要加自定义昵称功能（新存档字段，另立 ADR）。
