# 唐小诗环游记：墨潮远征重构 Brief

> 版本：Deep Reboot 2.0
> 角色：游戏设计与实现验收基准
> 目标：把现有“诗文目录 + 五题四选一”升级为有旅程、有风险决策、有临场构筑、有剧情回馈的短局游戏。

## 1. 设计判断

当前项目已经有可靠的答题状态机、题库、存档、诗印和视觉素材，但仍然不像游戏：

- 主循环是浏览文集、章节、作者、诗卡，玩家是在找内容，不是在做决定。
- 绝大多数操作只有“点一个正确选项”，诗签是一次性工具，不会形成策略。
- 世界观只出现在标题、背景和作者对白里，答题的结果没有改变旅程。
- 5 题一轮的奖励主要是分数和诗印，玩家没有短期资源、路线取舍或构筑目标。
- 题目反馈做得很清楚，但仍是“学习工具式反馈”，缺少风险、悬念和下一步期待。

本次重构要改变的是玩法骨架，不是继续增加统计字段或给列表加装饰。

## 2. 新定位

**一句话：**

> 唐小诗在“墨潮”吞噬古诗之前，沿三条诗境墨路修复失声的诗页；每一页都要在有限的诗火中作答、取舍和冒险。

**玩家身份：**唐小诗，携带一盏诗火和一卷空白诗册的修页人。

**世界冲突：**墨魇不是一个具体的坏人，而是从诗句空白处蔓延的“遗忘”。它抹去诗中的关键句，使诗境失去声音。作者不再是被点击的头像，而是每个诗境的守卷人；玩家完成一页诗，才会让对应守卷人的声音恢复。

**受众：**小学高年级到初中生，也要让家长觉得有审美、有学习价值，不做考试页面，不做恐怖叙事。

## 3. 体验支柱

### 3.1 每局都要有路线决定

进入“远征”后不直接进入目录。玩家看到 3 个带有不同风险与收益的墨路节点：

- **青灯小径**：较稳，额外机会更多，奖励普通。适合第一次接触或想稳通关。
- **风雨险滩**：机会较少，但连击和诗印收益更高。适合熟悉题目的玩家。
- **无名残卷**：隐藏信息，题目来自随机文集，完成后获得一次强力临场能力。

三个节点必须使用现有题库真实诗卡，显示文集、作者、诗名、风险标签和可见奖励。不能出现“随机”但不告诉玩家任何信息的空洞按钮。

一次远征最多 3 个节点：节点 1 建立节奏，节点 2 让玩家选择修复/冒险，节点 3 是“潮头”终章。完成 3 个节点显示远征结局，不要求一次新增大量内容。

### 3.2 每局有轻量构筑

保留现有三枚诗签，但从“开场一次性按钮”提升为每局的策略核心：

- **明心**：本页一次，隐藏两个错误项；完成节点后若表现优秀，可升级成“明心·再照”（下一节点仍可用一次）。
- **护卷**：首次错误不损失诗火；适合稳健路线。
- **回响**：第一次连续答对后的下一题得分与诗火奖励翻倍；适合追求连击。

每完成一个节点，出现二选一的“修页奖励”，并且必须立即影响下一节点：

- **续灯**：恢复 1 盏诗火。
- **磨墨**：下一节点首个正确答案额外得分。
- **听句**：下一节点开局先显示一行诗文上下文，降低第一次选择压力。

不要引入装备栏、稀有度、抽卡、付费货币或复杂技能树。总共只有“诗火、连击、当前诗签、一个修页奖励”四类短期状态。

### 3.3 答题结果要改变旅程

- 正确：修复当前诗页，增加连击/诗火能量，节点地图上的墨色退去一部分。
- 错误：墨潮前进，损失诗火并切断连击；玩家仍看到正确诗句和上下文。
- 同一节点表现决定奖励质量：零错误/高连击显示“清声”，有错误但通关显示“留痕”，失败显示“未能收句”。
- 第 3 个节点结束后，根据累计表现给出三种短结局标题：`诗声复明`、`带伤归卷`、`墨潮未退`。不做长篇剧情树，做有明确因果的短回收。

## 4. 内容与叙事

### 4.1 三幕远征文案

只需编写一套可复用的短文案，不改写 2147 首诗的原始内容：

1. **起潮**：城门外的诗碑只剩空白，唐小诗拿到第一盏诗火。
2. **入墨**：守卷人告诉玩家，墨潮最怕“连续想起”，需要在风险路线上找回断句。
3. **潮头**：第三页出现全局标题“失声的诗页”，玩家带着本局状态完成最后一轮。

作者首次相遇对白继续复用，但文案语义统一为“守卷人/诗境回声”，不要让作者像答题 NPC 或敌人。

### 4.2 叙事出现的地方

- 首页：当前远征状态、墨潮进度、下一节点摘要、唐小诗状态。
- 路线选择：每条路有一句短叙事和清楚风险收益。
- 节点开始：诗名、作者、守卷人一句话、当前奖励。
- 反馈层：不是只显示“答对”，而是显示“诗页补回一行”或“墨潮抹去一盏诗火”。
- 远征结束：结局标题 + 本局旅程摘要 + 下次可尝试的路线/诗签。

文本应短、口语化、可跳过。禁止教程墙和大段赏析。

## 5. 页面架构重构

### 5.1 首页：远征台，而不是四入口菜单

首屏必须回答三个问题：我在哪、接下来去哪、为什么现在开始。

- 顶部显示 `墨潮远征`、当前幕数 `1/3`、诗火、累计诗印。
- 中央为唐小诗与当前守卷人/诗碑的场景组合，复用现有素材。
- 主按钮只有一个：`继续远征`（未择墨路时显示「去择墨路」）；新存档为 `点亮第一盏诗火`。
- 下方是横向的三节点旅程条，当前节点高亮，完成节点显示诗印/结局标签。
- `文集`（诗集资料库 `/library`）、`诗库`、`墨潮试炼`、`诗册`作为次级入口，放到低对比度底部导航；练习已并入“诗库”。
- 不做四个同等权重的大卡片。

### 5.2 `/tour`：墨路选择页

将现在的文集网格改成“远征地图 + 节点选择”（落地时按 ADR-0017 进一步把文集网格迁到独立 `/library`，本页只留路线卡）。每次节点选择展示三个路线卡：诗名/作者/文集、风险标签、奖励预览、节点序号。

### 5.3 诗题页：诗页修复场

保留现有 `/play/$poemId` 路由与题库，但重新包装视觉和布局：

- HUD：节点 `2/3`、诗火、连击、当前修页奖励、题目 `3/5`。
- 中部：诗碑/作者立绘 + 唐小诗，答对时墨色裂开、答错时墨痕蔓延；使用 CSS 与现有素材，不强制新增图片。
- 题面：把诗句当成“正在修复的缺行”，选项像四片可拼回的竹简。
- 正确反馈：`诗页补回一行`、本题得分、连击、下一步奖励。
- 错误反馈：`墨潮抹去一盏诗火`、正确句、相邻上下文；明确“收句”继续。
- 结算面板不只展示数字，要显示节点评价、获得的修页奖励和下一节点摘要。

### 5.4 其他页面

- `练习`保留三轴筛选，但标题改为“诗库”，明确它是自由学习入口，不是主线。
- `无尽`改为“墨潮试炼”，保留一错结束，但增加阶段里程碑（5/10/20 连对）和当前风险描述。
- `成就`改为“诗册”，顶部显示远征结局次数、诗印、最高连击，下面才是作者/文集/朝代收集。

## 6. 存档与规则建议

新增字段应向后兼容，旧存档打开即生成默认远征状态：

```ts
expedition: {
  act: 1 | 2 | 3;
  nodeIndex: 0 | 1 | 2;
  fire: number;
  bestFire: number;
  relic: "none" | "renew" | "inkstone" | "listen";
  selectedTalisman: TalismanId | null;
  currentPath: "safe" | "risk" | "mystery" | null;
  completedRuns: number;
  endings: { clear: number; scarred: number; failed: number };
}
```

若完整数据库迁移超出本轮风险，可先把“当前远征”做成客户端状态并在成功节点写入已有 `PlayerSave` 的兼容字段，但最终必须保证刷新页面后不会把正在进行的远征默默重置。

规则约束：

- 诗火建议上限 4，初始 3；答错通常 -1，安全路线节点奖励 +1。
- 一节点仍是现有 5 题，及格线和题库规则不要破坏旧存档。
- 远征状态只影响当前一局，诗印/最佳分数/成就继续永久保存。
- 旧的 `clearedPoems`、`poemRecords`、`totalScore`、无尽纪录全部保留。

## 7. 视觉标准

保留古风绘本，但加入“墨潮正在逼近”的动态层次：

- 主色不是单一棕色：纸米色 + 松青 + 朱砂红 + 少量墨紫/青黛作为状态色。
- 重要状态用形状、文字、动画同时表达，不只靠颜色。
- 当前节点使用呼吸边框/墨滴粒子 CSS；完成节点用印章；失败节点有静止的墨痕，不持续晃动。
- 题目选择项要像可拾取的竹简/诗片，保持现有 `choice-slip` 质感，避免 SaaS 卡片堆叠。
- 圆角保持克制，单个重复物件不超过 8px 圆角；不做渐变英雄页，不做装饰性大圆球。
- 360x800 与 430x932 必须同时可读；任何反馈层不能遮住题干、角色或“收句”。
- 所有重要按钮使用 lucide 图标或现有素材，配合短文字；返回、设置、声音、跳过等图标需有 aria-label/tooltip。

## 8. 借鉴原则

借鉴的是结构，不照搬美术：

- 《杀戮尖塔》：地图路线让玩家在风险、资源和未知之间做决定，信息可读但不把最优解直接给出。
- 《Inscryption》：桌面、卡片和叙事在同一视觉语法里，界面本身参与世界观；这里把诗题当作正在修复的诗页。
- Duolingo 的连续反馈：短期连续完成能形成节奏，但不使用惩罚性断签，不用排行榜压迫儿童。

## 9. 实施优先级

### P0：必须做

1. 首页改成远征台，只有一个主目标。
2. `/tour` 改成三节点风险路线选择，并能真实进入现有诗题页。
3. 诗题页引入远征 HUD、诗火、节点进度、修页奖励，答题结果改变这些状态。
4. 一局结束显示三种因果结局和再战理由。
5. 旧模式仍能进入，旧存档兼容，路由不死。

### P1：应该做

1. 节点完成后的二选一修页奖励。
2. 远征状态持久化与刷新恢复。
3. 诗库/墨潮试炼/诗册的命名与入口重排。
4. 关键状态动画和窄屏布局打磨。

### P2：有余力再做

1. 少量首幕专属对白。
2. 节点不同背景的墨潮叠层。
3. 按路线/结局统计个人旅程记录。

## 10. 验收清单

- 新用户登录后首屏 3 秒内能看出“继续远征”是唯一主目标。
- 点击主按钮后看到至少 2 个有实际差异的路线选择，而不是目录。
- 选择路线后能在 5 题内感受到诗火、连击、修页奖励和风险变化。
- 答对/答错不会自动跳题；反馈明确说明“诗页/墨潮/诗火”发生了什么。
- 完成节点后确实能选择奖励，并在下一节点可观察到效果。
- 完成/失败后能说清自己为什么得到该结局，也知道再玩可以换什么路线或诗签。
- 刷新页面不会丢失正在进行的远征；旧存档不报错。
- 360x800、430x932、桌面宽屏分别检查；`npm run typecheck`、`npm test`、`npm run build` 至少通过 typecheck 与 build。

## 11. 实现对照（2026-09-06）

本 brief 是设计基准，但下列边界以当前代码为准：

- P0 已实现：首页远征台、`/tour` 三路线、真实诗卡候选、诗火、远征 HUD、诗页/墨潮反馈、修页奖励、失败重走和两种可持久远征结局。
- 远征状态实际存于浏览器 `localStorage` 的 `tangxiaoshi.expedition.v1`，没有加入 `PlayerSave` 或数据库 migration；它能跨刷新恢复，但不跨设备、浏览器或账号隔离。
- `续灯` 领取时立即增加诗火；`磨墨` 只作用于下一节点第一题；`听句` 只显示下一节点诗文第一行；这些是当前实现的精确边界。
- 青灯小径优先从未通关池取卡，风雨险滩优先从已通关池取卡，无名残卷从全池取卡；路线加成进入现有诗卡最佳分和总分。
- “墨潮未退”是失败结算面板语义；失败节点会回到 pending，不会把整局永久标记为 failed。最终远征状态只持久化 `clear` 或 `scarred`。
- 诗签跨节点升级、远征结局历史、墨潮试炼 5/10/20 连对里程碑、三幕专属对白、账号级远征同步均未实现，属于后续计划。
