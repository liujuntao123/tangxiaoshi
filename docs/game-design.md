# 唐小诗历险记：游戏设计总案

> 版本：重做 1.0
> 
> 用途：定义“好玩”的目标、玩家体验和系统规则；实现、评审、试玩均以本文为准。

## 1. 产品定位

唐小诗历险记是一款给小学和初中生玩的竖屏古诗文冒险游戏。玩家扮演束发男童唐小诗，在被大魔王抽空文字的诗境中前进，靠记忆和判断击退妖怪，救出一位位诗人。

**体验承诺：**每次答题都像一次出招；每次答错都能看懂并继续；每关结束都有可比较的成绩；玩家总知道下一步要做什么。

## 2. 设计目标

### 2.1 三个核心支柱

1. **选择有意义**：每关开场选择一枚诗签，决定本局的容错或得分方式；战斗中还要判断是否使用一次性能力。
2. **反馈有节奏**：答题不是点击后自动跳走，而是经历“作答 -> 出招/受伤 -> 读结果 -> 主动收句 -> 下一题”。
3. **表现值得重玩**：通关只是最低目标，诗印、分数和连击让熟练玩家有提分理由。

### 2.2 明确不做

- 不做动作操控、走位、实时躲避或复杂技能树。
- 不做装备、抽卡、体力、付费货币和随机箱。
- 不做开放世界或自由探索型地图。
- 不做长篇赏析、文言教学讲义或强制阅读教程。
- 不用排名压迫儿童玩家；成绩是个人进步记录。

## 3. 玩家旅程

### 第一次进入

玩家看到唐小诗和“继续历险”，点一次即可进入当前目标，不需要在四个入口中猜路。第一次进入历险时用短对白说明：诗人被抓、诗变白、答对才能前进。

### 一局体验

玩家先选诗签，再连续完成一首诗对应的 3-4 道题。正确答案会让唐小诗攻击，错误答案会让他受伤。每题后都能看清正确项和相关诗句，玩家主动点“收句”继续。胜利后获得 1-3 枚诗印和分数，决定回地图或再战提分。

### 长期体验

玩家通过关卡解锁诗文、收集诗人卡和朝代卡；通过重复挑战提高诗印、分数和连击；无尽模式把已经学会的内容变成短时挑战。主线解锁负责给方向，练习负责降低学习门槛，成就负责展示积累。

## 4. 核心玩法循环

```text
主线目标
  -> 选择诗人章节
  -> 地图选择地点
  -> 选择诗签
  -> 四选一诗题战斗
      -> 正确：攻击、连击、诗气
      -> 错误：受伤、断连、看正确答案
  -> 胜利结算：诗印 / 分数 / 最高连击
  -> 解锁下一地点，或重战提高成绩
```

### 关卡长度

- 目标时长：60-90 秒，不含首次对白。
- 题目数量：直接使用该诗现有题目，通常 4 题。
- 玩家血量：3。
- 妖怪诗魄：3；连携攻击时可造成 2 点伤害。
- 每题只允许作答一次；结果确认后才能进入下一题。

## 5. 战斗系统

### 5.1 状态机

战斗实现必须是显式状态机：

```text
intro -> loadout -> battle -> resolving -> battle
                                  |-> outro -> result
                                  |-> lose
```

- `intro`：现有开场对白。
- `loadout`：选择一枚诗签，展示效果和开始按钮。
- `battle`：显示题目、四个选项、战斗 HUD。
- `resolving`：锁定选项，播放攻击/受伤反馈，展示结果，等待玩家收句。
- `outro`：现有结尾对白。
- `result`：结算成绩和按钮。
- `lose`：失败、重试或回地图。

任何阶段都必须防止重复提交。离开关卡时清理计时器，不能让旧回调改变新一局状态。

### 5.2 连击与诗气

- 连续答对，连击 +1；答错则连击归零。
- 正确答题获得诗气，使用 CSS 进度条显示。
- 连续答对 3 题后获得一次“连携”状态；下一次正确答案造成 2 点诗魄伤害，并清空连携状态。
- 连击是即时反馈和结算指标，不永久保存为战斗资源。
- 诗气不需要玩家复杂管理，只用于让连续正确有可见的节奏奖励。

### 5.3 三枚诗签

每局开始三选一，只影响当前挑战，重战可重新选择：

| 诗签 | 效果 | 适用玩家 |
| --- | --- | --- |
| 明心 | 战斗中使用一次，隐藏两个错误选项 | 不确定答案时降低干扰 |
| 护卷 | 第一次答错不扣血，但仍断连 | 想稳定通关的新玩家 |
| 回响 | 第一次答对后，下一题正确获得额外分数与诗气 | 熟悉题库、追求高分的玩家 |

诗签按钮必须显示名称、图标/符号、短说明和剩余次数。使用后显示已用状态；不可用时禁用并保留原因。

## 6. 题目反馈设计

### 答对

1. 选项变为正确态，其他选项锁定。
2. 唐小诗进入出招帧，妖怪进入受伤帧。
3. 显示“答对 · -1 诗魄”或“连携 · -2 诗魄”。
4. 显示连击变化和诗气变化。
5. 显示“收句”按钮，玩家点击后进入下一题。

### 答错

1. 选中的错误项变为错误态，正确项高亮。
2. 唐小诗进入受伤帧，若护卷生效则显示“护卷挡下了这一击”。
3. 显示正确答案和该句的相邻上下文，最多两行，不写长解析。
4. 连击归零；正常情况下玩家掉 1 血。
5. 显示“收句”按钮，玩家点击后进入下一题或失败页。

### 反馈原则

- 反馈必须可读、可操作、可等待；不能用短定时器替代确认。
- 颜色、文字、动画同时表达结果，不能只靠颜色。
- 低龄玩家即使答错，也能知道哪里对、为什么是这一句的位置。

## 7. 评分与成长

### 7.1 诗印

- 1 星：完成关卡。
- 2 星：胜利时至少剩 2 血，或最高连击达到 3。
- 3 星：全程未掉血并全题答对。
- 历史只保留最高星级，不因重战降低成绩。
- 普通关胜利继续给钥匙；重战不重复增加钥匙。

### 7.2 分数建议

- 普通正确：100 分。
- 连击加成：每多 1 层连击额外 +25 分，上限由实现控制在合理范围。
- 连携正确：额外 +100 分。
- 使用护卷后无额外惩罚，但无法获得“全程未掉血”条件。
- 结算页必须展示本局总分和历史最佳分数，刷新时明确提示。

### 7.3 存档

新增字段：

```ts
levelRecords: Record<string, {
  bestStars: 0 | 1 | 2 | 3;
  bestScore: number;
  bestCombo: number;
  attempts: number;
}>;
totalScore: number;
```

旧存档缺失字段按空对象和 0 处理。现有 `clearedLevels`、`keysOwned`、诗人/朝代成就、无尽成绩继续兼容。

## 8. 页面与导航

### 首页

首要按钮是“继续历险”：

- 找到最早一个已解锁且未通关的关卡。
- 全部当前内容通关时，定位到最近通关关卡并改为“再战提分”。
- 显示救出诗人数、已获诗印总数、无尽最高连对。
- 历险、无尽、练习、成就保留为次级入口。

### 章节地图

- 节点状态：锁定、可挑战、已通关、当前最好 1/2/3 星。
- 当前可挑战节点有轻微呼吸光效。
- 顶部显示钥匙进度和章节诗印总数。
- 已通关节点仍可点击重战。

### 无尽

规则仍是一题错本局结束，但使用主线相同的战斗表现：角色、攻击/受伤、连击、诗气、正确答案反馈。错题反馈后再进入结束页；结束页显示本局分数、连对、历史最佳和是否刷新纪录。

### 练习

保持可看全部诗文、查看答案、不扣血。增加当前诗文的题目进度和轻量完成标记，不增加长解析。

### 成就

保留诗人卡、朝代卡、“滴水不漏”和“十连击”。增加全局诗印总数、总分和无尽最高连对概览；不要扩展成新的图鉴系统。

## 9. 视觉与交互

- 保留古风绘本、卷轴、木牍、玉佩和现有场景素材。
- 舞台最大宽度约 430px；360x800 和 430x932 都要完整显示题干、角色、选项和结果按钮。
- 战斗选项应紧凑但可读；反馈层不能盖住题干和按钮。
- 只使用短促的攻击、受伤、连击和诗印动画；尊重 `prefers-reduced-motion`。
- 不引入网页 SaaS 卡片堆叠、渐变营销英雄区或复杂表单 HUD。
- 所有按钮有按下态、禁用态和清晰可访问名称。

## 10. 内容原则

- 现有诗题库和剧情继续作为内容来源，不在运行时生成题目。
- 妖怪只是诗境阻碍，不把题目包装成惩罚性考试。
- 对白短、口语化，一次只推进一个情节动作。
- 答错后的上下文优先使用诗句本身，不新增大段解释。
