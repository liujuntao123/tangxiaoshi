# 唐小诗历险记：可玩性重做 Brief

> 文档导航：总案见 [`game-design.md`](game-design.md)，工程拆解见 [`implementation-plan.md`](implementation-plan.md)，试玩验收见 [`playtest-checklist.md`](playtest-checklist.md)。

## 目标

把当前的“对白 -> 连点四选一 -> 返回地图”改成一个有明确节奏、选择、反馈、成长和重玩的短局游戏。核心仍然是诗题答题战斗，不引入动作操控、开放世界、复杂装备数值或后台内容编辑器。

一句话体验：**我选一枚诗签，带着连击在诗境里击退妖怪，答错会掉血，答得漂亮会留下更高的诗印。**

## 当前问题诊断

- 每题之间没有玩家决策，正确与错误只改变血条，像表单而不像战斗。
- 题目反馈自动消失，玩家没有确认答案、读懂错题、主动推进的节奏。
- 一关结束只解锁下一节点，没有战绩、评级或再战理由。
- 首页是四个入口，缺少“现在该做什么”的主目标。
- 无尽模式只有题目和数字，和主线的战斗幻想脱节。

## 不变的边界

- 竖屏 Web，最大宽度约 430px，继续使用现有绘本场景、立绘、木牍/卷轴贴图。
- 玩家只点四选一和少量明确的战斗按钮，不走位、不施放动作技能、不填空、不语音作答。
- 诗人章节、朝代解锁、钥匙、三种模式和现有内容库继续有效。
- 不新增必须依赖的图片；优先复用 `public/art`、`public/sprites`、`public/ui`，用 CSS 做血条、连击、进度条和状态效果。
- 老存档必须能继续打开，新增字段有默认值；服务端和 PGLite 的 schema 同步。

## 核心循环

### 一关（约 60-90 秒）

1. 进入关卡，播放现有开场对白。
2. 出现“选诗签”准备段，从三枚固定功能诗签中选一枚。选择后立即开始战斗，不做教程长文。
3. 进行该诗的全部题目（通常 4 题；按题库实际数量），每题是一回合。
4. 选对：唐小诗出招、妖怪掉 1 点诗魄、连击 +1、诗气增加；连续答对会触发更强的连携攻击。
5. 选错：唐小诗受伤、玩家掉 1 血、连击归零；锁定选项后明确显示正确答案和对应诗句，玩家点“收句”才进入下一题。
6. 妖怪诗魄归零进入现有结尾对白；玩家血量归零进入重试页。
7. 胜利结算展示本局分数、最高连击、剩余血量和 1-3 枚诗印；玩家可以收下奖励回地图，也可以立即再战提高评级。

### 诗签（三选一，单局一次性能力）

诗签不是永久装备，也不增加复杂数值，只给每次挑战一个轻量策略：

- **明心**：战斗中可用一次，隐藏两个错误选项。
- **护卷**：本局第一次答错不掉血，但仍会断连击。
- **回响**：本局第一次答对后，下一题额外获得连击分和诗气。

准备段要让三个按钮都有名称、图标/符号和一句极短效果说明；选中后有明显状态。战斗中只显示当前诗签和剩余次数，能力按钮在可用时可点。

### 战斗节奏

战斗顶部持续显示：

- 唐小诗血量和妖怪诗魄，使用现有 `HpPips` 或同风格图形。
- `连击` 数字与短促的连击动画；连击至少 2 时显示下一次连携提示。
- 诗气进度条；连续答对 3 题时形成一次“连携”，下一次正确答题造成 2 点诗魄伤害或等价的明显奖励。不要让玩家额外管理复杂技能树。
- 回合/题目进度，例如 `2 / 4`。

每次作答后必须有一个可读的结果状态，不能立刻自动切题：

- 答对：显示“答对 · -1 诗魄”、连击变化、短动画和声音。
- 答错：显示“答错”、正确选项、该句在诗中的上下文；不要写长篇解析。
- 结果状态提供一个清晰的“继续/收句”按钮，点击后才进入下一题。
- 计时可以作为轻量节奏条使用，但超时必须等同答错且给出相同的正确答案反馈；如果实现计时，给儿童足够时间（建议 12 秒），不要让动画或网络状态误伤答题。

## 评级与成长

每关胜利按本局表现得到 1-3 枚诗印：

- 1 枚：完成关卡。
- 2 枚：胜利时至少剩 2 血，或最高连击达到 3。
- 3 枚：全程未掉血且达到该关全部题目连击（全对）。

评级只取历史最好值。地图节点显示已获得的诗印，章节页显示章节总诗印；重玩已通关关卡可以提升评级，不重复发钥匙、不破坏解锁状态。

建议扩展 `PlayerSave`：

```ts
levelRecords: Record<string, {
  bestStars: 0 | 1 | 2 | 3;
  bestScore: number;
  bestCombo: number;
  attempts: number;
}>;
totalScore: number;
```

旧存档读取时缺失字段使用空对象和 0。`applyLevelWin` 接受本局结果，合并历史最佳；现有 `clearedLevels`、`keysOwned`、诗人/朝代成就和无尽最高分逻辑继续保留。新增数据库字段应通过新的有序 migration 完成，例如 `level_records` JSON 文本和 `total_score` 整数，并同步更新 server validator、读写和 PGLite。

## 页面改造

### 首页

- 第一视觉改成明确的主按钮“继续历险”：定位到当前最靠前的已解锁未通关关卡；全部通关时定位到最近一关并显示“再战提分”。
- 主按钮旁显示救出诗人、已获诗印和最高连击等真实进度。
- 四个模式入口保留，但降低为次级导航；无尽入口可以显示当前最高连对。
- 不增加营销式说明，不做卡片堆叠。

### 章节地图

- 保留现有地名路径和行走动画。
- 节点区分锁定、可挑战、已通关、当前最佳诗印；当前可挑战节点要有明显呼吸/光效。
- 顶部除钥匙外显示章节诗印总数。
- 已通关节点仍可点击重战；Boss 节点清晰标记但不改变原有钥匙门槛。

### 关卡

- 在 intro 和 battle 之间增加准备段。
- 将战斗实现为明确状态机，至少区分 `intro / loadout / battle / resolving / outro / result / lose`，清理延迟回调导致的重复点击和旧状态串线。
- 结果页提供：诗印、分数、最高连击、剩余血量；按钮为“收下诗印/回地图”和“再战一次”。
- 胜利时继续使用现有结尾对白，但不要让结算信息被对白吞掉。

### 无尽

- 继续“一题错，本局结束”，但复用主线战斗的角色、妖怪、连击、诗气、答对/答错反馈和结果节奏。
- 每题正确增加分数和连击，连续答对有递增分；错题明确展示正确选项后再进入本局结束页。
- 开始页显示历史最高连对/分数；结束页同时展示本局连击和是否刷新纪录。

### 练习与成就

- 练习保持无伤、可查看答案的定位，增加当前诗文的“已答题数/题目总数”或轻量完成标记，让它不是静态题库；不要添加长篇白话解析。
- 成就页在现有诗人卡、朝代卡、挑战成就下方增加全局诗印/最高连击概览；未获得卡片继续保持可辨认但不喧宾夺主。

## 视觉和交互验收

- 首屏 430x932 与窄屏 360x800 均不能让选项遮住角色、题干被截断或按钮超出视口；宽桌面仍居中为竖屏舞台。
- 选项、诗签、继续按钮有明确按下态、禁用态、正确/错误态；键盘和屏幕阅读器能读出按钮状态。
- 动画只强化攻击、受伤、连击、诗印获得，不做持续晃动；尊重 `prefers-reduced-motion`。
- 不引入网页 SaaS 卡片风、渐变英雄页、复杂表单式 HUD；保持现有古风绘本质感。
- 每个可玩的状态都能到达下一状态，切换路由、刷新页面、重试关卡不会卡死。

## 工程验收

- `npm run typecheck` 通过。
- `npm run build` 通过，包含数据库 migration 检查。
- 现有 auth、登录、路由、旧存档兼容逻辑不回归。
- 至少补充纯函数测试或可测试的 progress 逻辑覆盖：评级合并、诗印计算、旧存档默认值、无尽纪录更新。
- 完成后在本地 dev/preview 中手动验证：新用户进入首页、开始一关、答对/答错、使用诗签、胜利评级、重战提分、无尽刷新纪录、刷新后存档仍在。
